# DateMate

DateMate 是一个用于知识表示与推理教学的约会活动规划示例，采用纯前端实现，适合通过 GitHub Pages 发布。项目使用框架表示描述活动，用产生式规则筛选和组织方案，并以实际规则记录解释推荐依据。

项目中的活动、费用、地点和其他数据均为虚构教学示例。使用者应自行核实实际场所、开放时间、天气与费用，示例方案用于展示推理过程。

### 基础功能

基础页面围绕六组输入、生成与清空操作、方案 A 时间线及推荐依据组织交互。筛选条件包含活动范围、预算和排除地点；规则处理雨天、疲惫等情境。高级面板提供天气、互动和随机性设置，人格设置作为后续扩展占位。

活动框架包含费用、时长、校内或周边、室内或室外等槽位。规划器根据输入应用规则，推荐理由来自实际触发的规则记录。后续资料可以补充到 `data/activities.mjs`，相应推理逻辑可以扩展到 `planner.mjs`。

基础实现采用以下文件分工，无依赖、构建步骤或后端服务：

| 文件 | 职责 |
| --- | --- |
| `index.html` | 页面结构与输入控件 |
| `styles.css` | 页面样式 |
| `app.mjs` | 页面交互与结果呈现 |
| `planner.mjs` | 筛选、规划与规则记录 |
| `data/activities.mjs` | 虚构活动框架数据 |
| `tests/planner.test.mjs` | 规划器测试 |

预算按两人费用区间的上限控制；仅校内、室内、忌口和排除地点等条件会参与筛选。规划器按偏好排序后贪心选择最多三个不同类型的活动，随机性为 0 时使用固定排序，当前算法不保证全局最优。关系、行为、心情、时期及生理状态保留为本次备注，待后续资料补充规则。

表单条件由浏览器内的规划器处理，保留在当前页面内存中，刷新页面后重新填写。

### 本地预览与测试

在项目根目录运行以下命令，需要本机已安装 Python：

```sh
python -m http.server 8080
```

随后访问 [http://localhost:8080](http://localhost:8080)。页面使用 JavaScript 模块，应通过 HTTP 预览；直接打开 `index.html` 的 `file://` 地址可能导致模块加载失败。

使用已安装的 Node.js 运行规划器测试：

```sh
node --test tests/planner.test.mjs
```

测试结果以实际命令输出为准。页面验收还应检查六组输入、生成与清空、时间线、规则依据，以及高级设置对结果的影响。

### 发布到 GitHub Pages

源码仓库为 [bylsxy/datemate](https://github.com/bylsxy/datemate)，站点地址为 [https://bylsxy.github.io/datemate/](https://bylsxy.github.io/datemate/)。部署状态可在仓库 `Actions` 页面查看。

将项目文件放在仓库 `main` 分支根目录后，按以下步骤配置：

1. 打开仓库的 `Settings` → `Pages`。
2. 在 `Source` 中选择 `Deploy from a branch`。
3. 选择 `main` 分支与 `/(root)` 目录，然后点击 `Save`。
4. 等待部署完成，再访问站点并检查页面与模块加载。

配置依据见 [GitHub 官方发布源文档](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site)。

出现 404 时，检查 Pages 的分支和目录选择、该位置是否包含 `index.html`，以及部署是否完成。页面打开但样式或交互缺失时，在浏览器开发者工具中检查资源请求与模块错误。项目站点位于 `/datemate/` 子路径，HTML 资源引用与模块导入应使用正确的相对路径，例如 `./styles.css`、`./app.mjs` 和 `./data/activities.mjs`；以 `/` 开头的资源地址会指向域名根目录。还需检查文件名大小写与实际文件一致。

### 知识表示与课程定位

课程要求涵盖至少两种知识表示方法、真实行业案例、小型推理与局限分析，并通过报告、PPT 和 demo 交付。DateMate 的基础选型为框架表示与产生式规则，提供可解释的小型推理演示。

| 方法 | 在项目中的用途 | 主要局限 |
| --- | --- | --- |
| 框架表示 | 用费用、时长、范围和室内外等槽位统一描述活动，支持条件比较与筛选。 | 槽位依赖人工设计，难以覆盖复杂情境与关系。 |
| 产生式规则 | 用条件与动作表达雨天、疲惫、预算等约束，并记录触发规则以解释推荐。 | 规则需要维护，冲突处理与覆盖范围影响结果质量。 |

完整课程交付仍需补充有来源支持的真实行业案例、实测结果、局限分析，以及报告、PPT 和 demo。当前虚构数据用于教学演示，尚不能支持对真实推荐效果的结论；人格建模、真实资料接入和更复杂的推理属于后续扩展方向。
