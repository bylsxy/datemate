### 教师要求与策划书实施验收

本文件根据工作目录中的教师作业截图、课堂报告参考模板及 DateMate V2.0 策划书提炼。最终报告中的实现规模和测试结论以本次源码、数据及实测结果为准。

### 策划书必须实现的交互

| 编号 | 要求 | 可观察验收条件 |
| --- | --- | --- |
| UI01 | 零输入先给完整推荐；条件表单均可选。 | 首次打开即可查看多阶段方案，无需问答或填写表单。 |
| UI02 | 每个阶段采用同一交互：纵向阶段、横向场景、点击选中。 | 横滑、悬停、聚焦不改变选择或输出指纹。 |
| UI03 | 场景卡内部只显示居中名称、推荐指数百分数、有实质内容的简短说明。 | 卡内无二次确认、详情、删除按钮，无资源表或图谱；资源和解释放卡外。 |
| UI04 | 点击整张场景卡即选中，有色边框和轻微放大，其余卡灰色。 | 不要求再点确认按钮；键盘可操作且选中状态明确。 |
| UI05 | 活动按组声明单选或多选，最低选择数为0。 | 再次点单选活动可清空；多选可全部取消；场景基础资源仍计入。 |
| UI06 | 只展示当前场景支持的活动。 | 场景改变时旧活动ID清除，新默认活动可见并可取消。 |
| UI07 | 场景与活动共同更新双方模型状态，并重算受影响后缀。 | 第k阶段修改保留前面阶段，当前活动资源和全部后续重新计算。 |
| UI08 | 休息是独立场景，没有活动卡，休息后可继续。 | 休息占时间、有限恢复、无连续无限休息。 |
| UI09 | 输出区域放置0—100“规划随机性”滑块，语义为确定性探索度。 | 同一规范化输入、固定选择、探索度及版本可复现；0→高值→0恢复输出。 |
| UI10 | 探索提高新鲜感和组合变化，硬限制先于所有软分数。 | 高探索不会放宽预算、时间、排除、安全与同意要求。 |
| UI11 | 系统默认推荐不自动等同用户确认；点第k阶段形成固定前缀。 | 探索只重算未确认后缀；“释放已选”允许从头重算；撤销恢复完整状态。 |
| UI12 | 修改硬条件后检查固定选择冲突。 | 提示用户释放/撤销；不自动增加预算、延长时间或缩短转场。 |
| UI13 | 不强求填满时段，自然结束。 | 无合格候选时结束并说明原因；无顶部“已规划x分钟”进度条。 |
| UI14 | 手机优先，露出下一张卡提示横滑。 | 触控区域约44px、文字无截断、整页无横向溢出、键盘/读屏状态清楚。 |
| UI15 | 推荐指数与现实可行性边界可理解。 | 百分数表述为模型排序指数；地点是场景类型；现实开放与价格需用户确认。 |

### 课程核心要求

1. 清楚运用至少两种主流知识表示方法，说明核心逻辑、优缺点与典型场景。本项目对应知识图谱/语义关系网络和产生式规则，两者必须参与真实候选计算。
2. 结合一个真实行业案例，说明知识表示与推理技术的落地流程。应引用产品官方资料，并区分公开业务能力与本组实现。
3. 独立演示一个小型推理任务，展示输入事实、图谱路径、规则触发及方案结果。
4. 客观分析现存局限和发展方向。

### 报告模板章节

| 顺序 | 教师模板章节 | 要求 |
| --- | --- | --- |
| 一 | 标题 | 技术＋场景。 |
| 二 | 摘要 | 约300字，目标、核心算法、实现步骤、实际测试结果。 |
| 三 | 关键词 | 3—5个，分号分隔。 |
| 四 | 背景与目标 | 300—400字。 |
| 五 | 相关技术与工具准备 | 400—500字。 |
| 六 | 算法设计与实现 | 600—800字，原理、公式/流程图、步骤、核心代码与注释。 |
| 七 | 测试结果与分析 | 400—500字，环境、评价指标、耗时与部署情况、图表、优缺点。 |
| 八 | 问题与改进思路 | 300—400字。 |
| 九 | 总结 | 200—300字。 |
| 十 | 参考文献 | 至少5篇，规范、可核查。 |

模板中的训练、学习率等是通用示例；本项目记录知识构建、规则调试与规划测试。组别、班级、姓名和学号待本人补充。
