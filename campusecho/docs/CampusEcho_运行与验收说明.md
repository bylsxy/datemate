# CampusEcho 运行与验收说明

第24组

成员：徐阳、廖信同、黎欣欣、周艳雯、殷浚峰

日期：2026-11-18

CampusEcho 是一个面向校园多跳问答的可审计知识图谱搜索系统。用户从公开问题卡或图谱实体出发，在 BFS、A*、GA-A*、GA+分类器、MCTS 与受限 LLM 引导之间比较搜索路径；选中可信结论后，可以把候选答案、证据、人员与资源约束带入校园任务沙盒，并通过服务端回执确认方案是否写入任务。项目同时包含完整代码、冻结实验、课堂报告、两分钟汇报、真实运行演示和研究图。

## 课程要求对照

| 课程要求 | 当前实现 | 可核验证据 |
| --- | --- | --- |
| 领域知识图谱与 2 至 4 跳问题 | 学术层与虚构校园层统一建模，包含实体、关系、三元组、来源、时间、家族划分和私有答案隔离 | `data/kg` 包含 504 个实体、1234 条三元组、662 道核心问题和 112 道稳健问题 |
| BFS、A*、MCTS 三套搜索内核 | `kg_search.py` 统一状态、动作、转移、终止条件、预算、轨迹和指标记录 | 正式测试 160 题，五种方法共享同一问题集合与搜索预算 |
| 启发函数与 GA 优化 | `kg_learning.py` 使用目标接近度、证据支持、路径效率和前沿平衡四维特征；`kg_hybrid.py` 将 GA 权重接入 A* 排序 | 冻结权重为 `[0.6630, 0.0628, 0.0779, 0.1963]`，GA-A* 的扩展节点与候选检查均低于 BFS |
| LLM 搜索辅助 | `llm_gateway.py` 只允许模型评价给定候选或解释已验证路径；动作合法性、路径奖励、停止条件和答案由本地代码决定 | 官方 DeepSeek 已完成真实候选评分与路径解释验证；非法动作被拒绝，错误输出会降级到本地搜索 |
| 机器学习与专家规则 | 带 L2 正则的逻辑回归路径价值分类器与关系白名单、图层、家族、无环、跳数、动作合法性和证据引用规则共同工作 | 验证集 2461 个样本，正样本 2162、负样本 299，冻结阈值 0.80 |
| 对比实验与失败分析 | 比较答案准确率、路径有效率、完整率、扩展节点、候选检查、推理步数、冗余比例和耗时；报告包含 MCTS rollout、GA 早熟、分类器交换和完整率口径分析 | 正式测试形成 800 条逐题记录，状态 `complete`，错误数 0 |

## 正式结果

测试集包含 107 道可解题和 53 道无解题。五种方法对 107 道可解题均返回至少一条标准有效路径，对 53 道无解题均返回空集。答案准确率、路径有效率和主指标成功率均为 1.0。

| 方法 | 平均扩展节点 | 平均候选检查 | 答案准确率 | 路径有效率 | 完整率 |
| --- | ---: | ---: | ---: | ---: | ---: |
| BFS | 5.01875 | 8.45625 | 1.0 | 1.0 | 0.13125 |
| 手工 A* | 8.5625 | 14.08125 | 1.0 | 1.0 | 0.13125 |
| GA-A* | 3.59375 | 5.2125 | 1.0 | 1.0 | 0.13125 |
| MCTS | 1.83125 | 8.10625 | 1.0 | 1.0 | 0.13125 |
| GA-A*+分类器 | 3.2 | 7.21875 | 1.0 | 1.0 | 0.13125 |

GA-A* 相对 BFS 减少约 28.39% 的扩展节点和 38.36% 的候选检查。MCTS 的树节点扩展数最低，但 rollout 工作量另计。分类器把平均扩展节点从 3.59375 降到 3.2，同时把候选检查从 5.2125 提高到 7.21875，应表述为排序交换，不能概括为全面更优。

严格完整率为 0.13125。每种方法有 21 题返回全部标准路径，53 道无解题返回空集但被当前完整率实现计为不完整，86 道可解题返回标准路径的非空真子集。该指标用于评价证据集合覆盖，主指标用于评价问答是否可用。

## 运行

项目要求 Python 3.12 或更高版本。在项目根目录执行：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[dev,web]"
.\.venv\Scripts\python.exe -m campusecho serve --port 8842
```

浏览器访问 `http://127.0.0.1:8842/`。首页提供知识搜索与校园任务沙盒，`http://127.0.0.1:8842/classic` 保留机制实验界面。

现场演示建议按以下顺序进行：

1. 选择一个自然语言多跳问题，运行 A*，播放完整搜索轨迹并查看每一跳来源。
2. 切换到 MCTS、GA-A* 和 GA+分类器，观察扩展节点与候选检查的变化。
3. 运行五种策略同题对照，说明 GA-A* 的效率、MCTS 的 rollout 成本和分类器的交换关系。
4. 将有效路径带入校园任务沙盒，选择任务、人员和时间预算。
5. 采纳方案，展示回执、路线和角色现场状态更新。

## 复现与检查

正式冻结结果位于 `artifacts/kg/formal_test_20261118`。重新运行实验时使用新的空目录：

```powershell
.\.venv\Scripts\python.exe tools\run_kg_experiment.py --output artifacts/kg/repro_20261118
```

常用检查命令：

```powershell
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m ruff check src tests tools
node --check src\campusecho\static\research.js
```

当前验证结果为 339 项测试通过，Ruff 与 JavaScript 语法检查通过。课堂报告共 16 页，包含 5 张研究图、1 个结果表和 11 个展示公式；两分钟汇报为 6 页、120 秒；真实运行演示为 13.88 秒，完整保留旁白和采纳回执。

## LLM 配置

工作台在存在 `DEEPSEEK_API_KEY` 时启用官方 DeepSeek 兼容接口：

```powershell
$env:DEEPSEEK_API_KEY = "<api-key>"
.\.venv\Scripts\python.exe -m campusecho serve --port 8842
```

凭据只从环境变量读取，不写入源码、日志、缓存键或交付回执。官方 DeepSeek 已完成真实候选评分和路径解释验证。正式冻结的 800 条搜索记录没有混入 LLM 评分，因此当前材料不宣称稳定 LLM 收益；LLM 的工程价值体现在受限调用、严格校验、证据引用和失败降级。
